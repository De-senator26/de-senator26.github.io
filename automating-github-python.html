Automating GitHub with the API and Python: a stale-repo report

By Tombir Anslem Swengka, 20 October 2026

Every developer’s GitHub account collects half-finished projects. Mine had nine repositories, and I wanted to know at a glance which ones I had stopped touching. Checking each one by hand is slow, so I wrote a small Python script that asks the GitHub API and prints a report.

Here is what it printed for my own account:

name                      language    stars  open_issues  days_since_push  stale
automation-scripts        Python      0      0            0                no
portfolio                 HTML        0      0            13               no
cornhouse-cm              Python      0      0            42               no
smart-farm                -           0      0            53               no
SMART-FARMER-MARKETPLACE  -           0      0            103              no
MERN-TASK-APP             JavaScript  0      0            406              yes
responsive-navbar         -           0      0            434              yes
forget-password           CSS         0      0            805              yes
my-cv                     HTML        0      0            838              yes

9 repos, 4 stale (no push in 180+ days).

Four of nine repositories had not been touched in over six months. That is the kind of thing you never notice until you look.

How it works

1. Ask the API for your repositories. GitHub lists every public repository for a user at /users/{user}/repos. The script requests them 100 at a time and keeps going until a page comes back empty, so it works whether you have 9 repositories or 900:

resp = requests.get(
    f"{API}/users/{user}/repos",
    params={"per_page": 100, "page": page, "type": "owner"},
    timeout=15,
)

2. Work out how long each repository has been quiet. The API returns a pushed_at timestamp for each one. The script subtracts it from today’s date to get the number of days since the last push.

3. Flag the stale ones. Anything with no push in 180 days is marked stale. You can change that with --stale-days. The table is sorted so the most recently active repositories appear first.

4. Export if you want. Add --csv report.csv and you get a file you can open in a spreadsheet.

python repo_report.py YOUR-USERNAME --stale-days 90 --csv report.csv

A word about tokens

You don’t need a token to run this on public repositories. Without one, GitHub allows 60 API requests an hour, which is plenty for a single report. If you want more, you can set a personal access token as an environment variable. Two rules matter:

  • Give the token read-only access, and nothing more than the script needs.
  • Never paste a token into your code or commit it to a repository. That is why the script reads it from GITHUB_TOKEN, and why the project’s .gitignore excludes .env files.

What I’d do with the results

Looking at the list, the four stale repositories tell the story of how I learned. responsive-navbar, forget-password and my-cv are early practice projects, so I’m archiving them. They stay visible as a record of where I started, but they no longer pretend to be active work. MERN-TASK-APP is different. It uses the MERN stack I work with most, so it’s worth either finishing or cleaning up with a proper README.

The bigger surprise went the other way: five of my nine repositories, including cornhouse-cm and smart-farm, have been pushed to in the last four months. That is the real value of a report like this. It doesn’t just show what you’ve neglected, it shows where your time is actually going.
